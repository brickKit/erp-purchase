# erp/purchase 的设计

本页写这个组件为什么这样设计：术语、拥有的数据、状态、规则要点、命令与事件、依赖、实现状态与未决问题。写给要修改它的人与 AI。怎样使用、部署与配置在 `BRICKKIT.md`；代码在哪、怎样构建与测试在 `AGENTS.md`。

跨组件的规则在装配项目：收货计价依据、采购退货与暂估在协议 05b，匹配依据、预付与供应商票据在协议 05，引用与资格在协议 07，单号、金额与汇率在协议 14，审批在协议 09，数据范围在安全 07；端到端的位置见装配项目的业务流程“采购到付款”。首批范围是装配项目阶段计划 C2 的 P0 定的（AI 定，待复核）。

## 边界

采购的申请、订单与它们的执行进度：收货（经库存入库）、服务验收、采购退货（经库存出库）；给成本的收货计价依据、给财务的匹配依据。

| 不在这里 | 归谁 |
| --- | --- |
| 库存余额、出入库流水 | `erp/inventory`（经它的系统面收货与退货；收货数量以它的入库流水为准） |
| 供应商票据、三单匹配、应付、预付 | `erp/finance`（向本组件查询匹配依据；预付申请是向财务的命令，本版没有） |
| 存货成本、暂估与调整 | `erp/costing`（消费收货计价依据与入库流水） |
| 付款 | `erp/payment` |
| 税额 | `erp/tax`（远期）；订单金额不含税，进项税由财务按票据算（D49） |
| 审批的统一待办 | `infra/workflow`（C7）；本版在本组件里审批 |
| 供应商、产品本身 | `mdm/partner`、`mdm/product`（引用时快照显示字段） |

## 术语

| 业务叫法 | 定义 | 代码标识符 |
| --- | --- | --- |
| 采购申请与申请行 | 部门提出的采购需要：产品、数量、需要日期；批准后转成订单行 | `requisition`、`requisition_line` |
| 采购订单与订单行 | 一个法人向一个供应商的订单；订单行是库存物资（`goods`，经库存入库）或服务与非库存物资（`service`，经验收） | `purchase_order`、`order_line`；`line_kind`：`goods`、`service` |
| 订单负责人、订单部门 | 采购自己拥有的字段，数据范围按它们限定（同销售） | `owner_id`、`department_id` |
| 修订 | 已批准订单的修改：新修订，回到待审批 | `revision` |
| 采购政策 | 按法人：要不要审批、超收比例 | `purchase_policy` |
| 收货与收货行 | 一次到货：订单的若干库存物资行与数量，经库存入库；收货行的身份是给库存与成本的“收货行参考” | `receipt`、`receipt_line`；状态 `receiving`、`posted`、`failed` |
| 已收数量 | 订单行收进的数量，取自库存的入库流水（按流水身份去重），减去采购退货 | `order_line` 的 `received_qty` |
| 服务验收 | 服务与非库存物资行按数量或金额验收 | `acceptance`、`acceptance_line` |
| 采购退货 | 引用一条收货的入库流水退回，经库存出库 | `purchase_return`、`return_line`；行状态 `returning`、`posted`、`failed` |
| 收货计价依据 | 每个收货行的单价（不含税）与币种，给成本暂估（协议 05b） | 事实 `erp.purchase_receipt.valuation_basis.v1` |
| 匹配依据 | 按订单行的订购、已收、已验收的数量与金额，供财务的三单匹配与期末暂估（协议 05、D50） | 系统面 `MatchService` |
| 部门投影 | 同销售：`mdm/org` 部门的投影，部门路径复制到单据上 | SDK 的投影 `org_units` |

## 拥有的数据

| 表 | 内容 | 终态与保留 |
| --- | --- | --- |
| `requisition`、`requisition_line` | 申请：单号、法人、部门（与复制的路径）、申请人、状态、版本；行：产品与快照、数量与单位、需要日期、已转订单的数量 | `closed`、`rejected`、`cancelled`；不删除 |
| `purchase_order` | 订单：单号、法人、供应商（与快照的名称、税号）、币种、业务日期、负责人、部门（与复制的路径）、状态、修订、合计（不含税）、提交人与审批人、版本 | `completed`、`closed`、`cancelled`；不删除 |
| `order_line` | 行：种类、产品与快照（代码、名称、单位）、数量与单位、基本单位数量、单价、行金额、仓库（库存物资）、预计到货日、来源的申请行、项目参考；进度：收货中、已收（净额）、已验收数量与金额 | 随订单 |
| `receipt`、`receipt_line` | 收货：单号、订单与修订、法人、仓库、状态、业务日期；行：订单行、数量、批次或序列号、入库流水身份 | `posted`、`failed`；不删除 |
| `receipt_movement` | 收进的入库流水（流水身份、收货行、数量）：已收数量的来源，按流水身份去重 | 随订单 |
| `acceptance`、`acceptance_line` | 服务验收：单号、订单、验收人、业务日期；行：订单行、数量、金额 | 不删除 |
| `purchase_return`、`return_line` | 退货：单号、订单、法人、原因；行：原入库流水、收货行、数量、序列号、状态、退货出库流水 | 不删除 |
| `purchase_policy` | 按法人的采购政策：要不要审批（起始：要）、超收比例（起始 0%） | 版本化 |
| 部门投影 `org_units`（SDK 的投影表） | 同销售 | 随来源 |

以后还有：预付申请、供应商价格表与询价、返利、已结束订单的数据类别（协议 11）。

规则目录（订单）：

| 规则 | 内容 |
| --- | --- |
| PO01 | 新建与申请转订单得到 `draft`；供应商在该法人的资格（用途 `purchase`）、每个产品的资格（用途 `purchase`，回答带是否库存物资）在事务外取证，W 内提交（协议 07） |
| PO02 | 只有草稿能修改 |
| PO03 | 只有草稿能提交；提交时重新取证（供应商、产品、法人）；法人的政策不要审批时直接批准（提交人即批准人，审计照写） |
| PO04 | 批准要操作 `erp.purchase.order.approve`；批准人不能是提交人（按账号；按自然人等业务确认 profile，C7） |
| PO05 | 驳回回到草稿，附原因 |
| PO06 | 修订：只有已批准的；新修订回到待审批（法人的政策不要审批时直接批准，同 PO03）；供应商与币种不变；保留的行按行身份，产品与来源的申请行不变，数量不低于已收、收货中与已验收；删除的行必须没有任何进度 |
| PO07 | 收货只对已批准订单的库存物资行；本次数量加收货中加已收不超过订购数量乘（1 + 超收比例），超出整笔拒绝 |
| PO08 | 验收只对已批准订单的服务行；同样受超收比例约束（数量维，或金额维） |
| PO09 | 退货引用收货的入库流水；已批准、已完成、已关闭的订单都能退；数量不超过该流水的净收货：采购在建退货单的事务里先查，超出整笔拒绝、不建退货行（`RETURN_EXCEEDS_RECEIPT`），库存在出库时再核对一次（并发的退货）；退货减少行的已收 |
| PO10 | 关闭：已批准的订单不再收货、验收；没有收货中的收货才行；未收部分作废（以后通知财务与预算） |
| PO11 | 取消：草稿与待审批的随时；已批准的只在没有任何收货、验收时（有了就关闭） |
| PO12 | 每一行都收足或验收足（净额达到订购数量）时订单完成；退货使净额回落时不回到已批准，补收走新订单（以后再看） |

## 收货、验收与退货

- **收货**（PO07）：建收货单（`receiving`，行带收货行身份），发布每个收货行的收货计价依据（单价取订单行、币种取订单），提交；然后在事务外调库存的 `StockService.Receive`（收货身份就是收货单身份，幂等）。成功：按回答的流水记 `receipt_movement`、加已收、收货单 `posted`。失败（库存答拒绝）：收货单 `failed`，收货中的数量退回，并在同一事务里发布每个收货行的计价依据撤回（`erp.purchase_receipt.valuation_basis_withdrawn.v1`，协议 05b 的“计价依据撤回”：没有流水用到它，成本只是删掉这个来源）。结果不明（超时、不可达）：保持 `receiving`，恢复作业按同一身份重发；库存的流水事件也会补上已收（下一条）。
- **按入库事实补齐**（验证故事）：订阅库存的流水事件，`ref_kind = purchase_receipt` 的入库按流水身份去重记进 `receipt_movement` 并加已收；同一收货单的流水齐了，收货单 `posted`。所以回调丢了、进程在调用之后崩溃，已收都以入库事实为准。收货单已经因库存拒绝而 `failed`、之后仍有它的流水到达时，流水照样计入已收（入库事实优先）。
- **验收**：服务行的验收单在一个事务里写，发布验收事实（数量、金额、收货行参考取验收行身份），给财务的期末暂估与匹配。
- **退货**（PO09）：退货单每行引用一条入库流水，在事务里建（`returning`），事务外逐行调库存的 `StockService.Return`（退货身份是退货行身份）；成功记退货出库流水、减已收、发布退货事实；拒绝记 `failed`；不明由恢复作业重发。

## 规则要点

- 金额：行金额 = 数量 × 单价，按币种的小数位舍入（协议 14）；订单不含税。单价在订单上录入（价格表以后）。
- 收货计价依据的单价：不含税、每基本单位（订单行金额 ÷ 基本单位数量，保留六位）；它的撤回的事实身份由计价依据的身份推出（UUIDv5，命名空间写在契约里），拿着计价依据、漏了撤回的消费方算得出撤回的身份，用 `FactService.Read` 读回。
- 收货的单位：订单行可以用采购单位，收货与退货给库存的是基本单位数量（`mdm/product` 的换算）。
- 已收数量只来自入库流水；收货单上的数量是请求，不是事实。
- 单号：申请 `PR`、订单 `PO`、收货 `GR`、验收 `SA`、退货 `RT`，按法人、按年的允许缺号序列，格式 `<前缀>-<法人代码>-<年>-<六位序号>`。
- 审计：提交、批准、驳回、修订、关闭、取消、收货与退货的结果都审计（协议 03：一个操作在写下业务的那个事务里审计）。

## 事件

流 `erp.purchase`：

- 完整状态事件（可覆盖）：申请 `erp.purchase_requisition.changed.v1`、订单 `erp.purchase_order.changed.v1`（带行与进度）、收货单 `erp.purchase_receipt.changed.v1`、退货单 `erp.purchase_return.changed.v1`。
- 增量事实（不可遗漏，协议 05 的共同规则；事实身份是收货行、验收行、退货行的身份，`FactService.Read` 按身份补取）：收货计价依据 `erp.purchase_receipt.valuation_basis.v1` 与它的撤回 `erp.purchase_receipt.valuation_basis_withdrawn.v1`（收货失败时）、验收事实 `erp.purchase_acceptance.recorded.v1`、采购退货 `erp.purchase_return.posted.v1`。

订阅：`mdm/org` 的部门事件（部门投影，同销售）；`erp/inventory` 的流水事件 `erp.inventory_movement.recorded.v1`（只取 `ref_kind = purchase_receipt` 的入库，按入库事实补齐已收）。
